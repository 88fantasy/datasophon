# T8 改写对照清单：Doris 方言 → Flink SQL

源：`docs/lineage/dwd层建表语句清洗语句.md` 第 2 节。目标：`docs/lineage/sql/dwd_odr_oper_surgery_records_full_hourly.sql`。

| # | 原文（Doris 方言） | 改后（Flink SQL） | 原因 |
|---|---|---|---|
| 1 | `ps.surgery_name`／`ps.doctor_dept_id`／`ps.doctor_dept_name` 等小写列名 | `ps.SURGERY_NAME`／`ps.DOCTOR_DEPT_ID`／`ps.DOCTOR_DEPT_NAME` | MySQL/Doris 列名大小写不敏感，Flink SQL 对未加引号的标识符按大小写敏感解析，且 Paimon 建表（T2）用的是源表大写列名，必须精确匹配 |
| 2 | `CASE ps.TYPE WHEN 1 THEN ...`（数字字面量） | `CASE ps.TYPE WHEN '1' THEN ...`（字符串字面量） | D10：ODS 全列 STRING，`ps.TYPE` 是字符串类型，Doris 里数字字面量能隐式转字符串比较，Flink SQL 类型检查更严格，直接用字符串字面量 |
| 3 | `JSON_VALID(ps.anes_assistant)` | `ps.ANES_ASSISTANT IS JSON ARRAY` | `JSON_VALID` 是 Doris/MySQL 专有函数，Flink 没有；用 ANSI SQL 2016 标准的 `IS JSON` 谓词代替，选 `ARRAY` 而非泛化的 `VALUE` 是因为后续 `$[0]` 路径本就假定是数组结构，语义更精确 |
| 4 | `JSON_UNQUOTE(JSON_EXTRACT_string(ps.anes_assistant, '$[0].name'))` | `IFNULL(JSON_VALUE(ps.ANES_ASSISTANT, '$[0].name'), '')` | `JSON_EXTRACT_string` 是 Doris 专有函数（返回 JSON 编码字符串，需要 `JSON_UNQUOTE` 再剥一层引号）；Flink 标准 `JSON_VALUE` 直接返回标量字符串，无需 `UNQUOTE`。外层加 `IFNULL` 是因为 `JSON_VALUE` 默认 `ON EMPTY`/`ON ERROR` 返回 `NULL`（路径取不到值时），而原 Doris 逻辑落到这个分支时不会是 NULL（分支前置条件已保证 JSON 合法），为了严格对齐"取不到就当空串"的整体语义，补一层保险 |
| 5 | `LOCATE('Ⅳ级', ps.SURGERY_LEVEL) > 0` | `POSITION('Ⅳ级' IN IFNULL(ps.SURGERY_LEVEL, '')) > 0` | Flink SQL 确认支持 `LOCATE(str1, str2)` 语义等价，但改用标准 `POSITION...IN...` 是因为 `LOCATE` 传 `NULL` 时行为未在 Flink 文档明确验证过；`POSITION` 是 ANSI SQL 核心谓词，`ps.SURGERY_LEVEL` 外包一层 `IFNULL(...,'')` 确保 `NULL` 不会导致整个表达式变 `NULL`（Doris 里 `LOCATE(x, NULL)` 返回 `NULL`，`NULL > 0` 是 `NULL`（假），会正确落到 `ELSE '未知'`；Flink 里同样处理但显式化，避免依赖未验证过的隐式行为） |
| 6 | `now()` | `CAST(NOW() AS STRING)` | `etl_time` 是 `VARCHAR`／`STRING` 列，Doris `now()` 隐式转到目标列类型；Flink SQL 类型系统不做这种隐式收窄转换，显式 `CAST` |
| 7 | `FROM ods_xxx ps LEFT JOIN ods_yyy psn ON ...`（批量视角，一次性 JOIN） | `FROM ps_with_proctime AS ps LEFT JOIN ods_yyy FOR SYSTEM_TIME AS OF ps.proc_time AS psn ON ...`（Lookup Join） | D1：`pat_surgery` 走 CDC 驱动主流，其余 7 张走 Lookup Join（维表关联，取"关联时刻"的最新维表值，而不是像批处理那样对整个维表做一次性 HASH JOIN）。Flink 流式关联的标准写法是时态表函数 `FOR SYSTEM_TIME AS OF <proctime>`，这是与原 SQL 语义差异最大的一处改写，不是纯语法替换而是执行模型的转变（批 JOIN → 流式时态 JOIN），对应 D1 的既定代价："维表变更不回溯刷新历史宽表" |
| 8 | （无对应项，原 SQL 里没有） | `CREATE TEMPORARY VIEW ps_with_proctime AS SELECT *, PROCTIME() AS proc_time FROM ods_smxt_lancet_aims_pat_surgery_full_daily;` | Lookup Join 语法要求主流有一个处理时间属性列做 `FOR SYSTEM_TIME AS OF` 的锚点；T2 建表时没预留这个计算列（不想为了这一个用途改动已经建好且被 T6/T7 依赖的物理表结构），改用 VIEW 包一层补上，不动物理表。**T9 实跑发现**：普通 `CREATE VIEW`（持久化进 Paimon catalog）不支持 `PROCTIME()` 这种非确定性函数，`UnsupportedOperationException`；改 `CREATE TEMPORARY VIEW`（会话级，不需要 catalog 持久化）才行 |
| 12 | （无对应项） | Doris sink 表声明改用 `CREATE TEMPORARY TABLE`（非 `CREATE TABLE`） | 同 #8 同源问题：Paimon catalog 不允许在其命名空间下创建非 Paimon 连接器的表（"Paimon Catalog only supports paimon tables"），凡是要在 `USE CATALOG paimon_s3` 上下文里声明外部连接器的表/视图，一律要用 TEMPORARY 变体 |
| 9 | `COALESCE(ee.jxksmc, dd.jxksmc)` | 不变 | `COALESCE` 是标准 SQL 函数，Flink 原生支持，无需改写 |
| 10 | `CONCAT_WS('、', ...)`、`IFNULL(...)` | 不变 | 两者都是 Flink SQL 内置函数，语义与 Doris/MySQL 一致，直接照搬 |
| 11 | `yblx`／`visit_id`／`sync_id`／`hzid` 硬编码 `null` | `CAST(NULL AS STRING)` | Flink SQL 对裸 `NULL` 字面量在某些上下文需要显式类型标注才能推断出结果列类型，尤其是这几列在 SELECT 列表里独立存在（没有其他表达式可供类型推断），加 `CAST` 避免类型推断失败 |

## 未改写、直接保留的部分

- 8 张 ODS 表名、DWD 表名、全部列名的语义映射（`AS xxx` 别名）——原样保留，改写只涉及函数/语法/JOIN 模型，不改数据语义
- `WHERE ps.VALID = 1 AND ps.IS_TRANSFER_ROOM = 0` → `WHERE ps.VALID = '1' AND ps.IS_TRANSFER_ROOM = '0'`（同 #2，数字字面量改字符串字面量，语义不变）

## 已知风险（留给 T9 实跑验证）

- `FOR SYSTEM_TIME AS OF` 对 Paimon 主键表的 Lookup Join 支持程度未经过真实执行验证，仅通过阅读 Flink/Paimon 官方文档确认语法合法；实际执行时可能需要额外的 `lookup.cache` 相关 WITH 属性，或触发未预见的 Flink 2.0.2 兼容性问题（参照 T4/T7 的踩坑密度，此处不假设"文档说支持就一定跑得通"）
